WCS

GWCS.jl exports the names in the first three sections of this page. The pipeline functions after them, and the names on the other API pages, are public but not exported: use them as GWCS.Step, or import them with using GWCS: Step.

GWCS.GWCS — Module
GWCS

Generalized world coordinate systems with composable, compiled transformations.

source

Reading and writing

GWCS.WCS — Type
WCS(steps::Step...; name="", pixel_shape=nothing, bounding_box=nothing)

A WCS pipeline: a sequence of coordinate frames, each Step holding a frame and the transform to the next, from the input (pixel) frame to the output (world) frame. Construction validates the pipeline and compiles its transforms once, for fast repeated evaluation with pixel_to_world and world_to_pixel. A WCS is immutable; editing functions such as set_transform return a new one.

Each step's transform maps its frame's dimension to the next frame's. The last step has no transform, and frame names are unique. An invalid pipeline throws an ArgumentError or a DimensionMismatch.

pixel_shape gives the image size along each pixel axis, with nothing for an axis without one. bounding_box, a BoundingBox or CompoundBoundingBox over the pixel axes, limits the input domain.

When every step has an analytical inverse, the WCS inverse composes them. Otherwise world_to_pixel solves numerically, which needs as many world as pixel axes.

Examples

julia> using GWCS

julia> using GWCS: Frame2D, Scale, Shift, Step

julia> wcs = WCS(Step(Frame2D(name="detector"), Shift(1.0) & Scale(2.0)), Step(Frame2D(name="world")));

julia> available_frames(wcs)
("detector", "world")

julia> pixel_n_dim(wcs), world_n_dim(wcs)
(2, 2)

Python equivalent: gwcs.WCS, which takes the steps as a list of (frame, transform) pairs.

GWCS.parse_wcs — Function
parse_wcs(node::AbstractDict; registry=default_transform_registry()) -> WCS
parse_wcs(yaml::AbstractString; registry=default_transform_registry()) -> WCS

Build a WCS from a tag:stsci.edu:gwcs/wcs metadata node, such as ASDF.load_file(filename)["wcs"] with ASDF.jl loaded, or from YAML text holding one. An astropy FITS WCS stored with asdf-astropy's wcs tag is read through parse_fits_wcs. Transforms are parsed by the tags registered in registry; see register_transform!.

Metadata that is malformed, uses an unsupported tag or schema version, or describes an invalid pipeline throws an ArgumentError naming its path in the tree. Properties GWCS.jl does not model are kept and written back by write_asdf.

GWCS.parse_fits_wcs — Function
parse_fits_wcs(header::AbstractDict; key=' ', preserve_units=false, minerr=0.0, legacy=:warn) -> WCS
parse_fits_wcs(header::FITSIO.FITSHeader; kwargs...) -> WCS
parse_fits_wcs(hdu::FITSIO.HDU; kwargs...) -> WCS
parse_fits_wcs(cards::FITSFiles.Cards; kwargs...) -> WCS
parse_fits_wcs(hdu::FITSFiles.HDU; kwargs...) -> WCS
parse_fits_wcs(hdus::AbstractVector{<:FITSFiles.HDU}, index; kwargs...) -> WCS

Build a WCS from a FITS image header. key=' ' selects the primary WCS, and a letter selects that alternate WCS. A header that is not a valid WCS throws an ArgumentError.

The header is a dictionary of keywords to values, or, with FITSIO.jl or FITSFiles.jl loaded, one of the objects above. To read the lookup-table and -TAB arrays a header refers to, pass a FITSIO.jl HDU, or FITSFiles.jl HDUs with the index of the HDU holding the WCS.

Pixel coordinates are zero-based, as everywhere in GWCS.jl, so FITS pixel p is GWCS pixel p .- 1; CRPIX needs no adjustment. World coordinates keep the header's axis order. They are in degrees for celestial axes, SI units for spectral axes, and seconds from the reference epoch for time axes, unless preserve_units=true keeps the header's CUNIT values.

A distortion whose D2IMERR or CPERR error estimate is below minerr is dropped, as astropy does. Legacy conventions that WCSLIB and astropy accept, such as NCP, AIPS spectral types, EPOCH, and zero-padded keyword indices, are repaired with one warning per parse when legacy=:warn, silently when legacy=:quiet, and rejected when legacy=:error.

Python equivalent: astropy.wcs.WCS, which evaluates the header with WCSLIB rather than building a GWCS pipeline.

Evaluation

GWCS.pixel_to_world — Function
pixel_to_world(wcs, pixels...; with_bounding_box=true, fill_value=NaN, strict=false, origin=0) -> SVector
pixel_to_world(wcs, pixels::AbstractMatrix; kwargs...) -> Matrix

Return the world coordinate of a pixel, in transform order and in the output frame's units. The pixel is given as separate numbers, a vector, or a tuple; a matrix holds one pixel per column and returns one world coordinate per column.

Pixels are zero-based: the center of the first pixel is 0 on every axis. origin=1 takes one-based pixels, as Julia array indices and FITS number them, by shifting every pixel axis by one; world coordinates are never shifted.

A pixel outside the bounding box, or one without a world coordinate, gives fill_value on every world axis. with_bounding_box=false ignores the bounding box. strict=true throws a DomainError for these pixels instead, and the error names the step and transform where the coordinate is undefined. With strict=true, a pixel that is already NaN gives NaN rather than an error.

Examples

using GWCS
using GWCS: Frame2D, Scale, Shift, Step

wcs = WCS(Step(Frame2D(name="detector"), Shift(1.0) & Scale(2.0)), Step(Frame2D(name="world")))
pixel_to_world(wcs, 1.0, 2.0)            # [2.0, 4.0]
pixel_to_world(wcs, 2.0, 3.0; origin=1)  # [2.0, 4.0]

Python equivalent: gwcs.WCS.pixel_to_world_values; Python's pixel_to_world returns astropy coordinate objects instead.

GWCS.world_to_pixel — Function
world_to_pixel(wcs, world...; with_bounding_box=true, fill_value=NaN, strict=false, origin=0,
               tolerance=1e-5, maxiter=30, initial_guess=nothing, max_backtracks=12, quiet=false) -> SVector
world_to_pixel(wcs, world::AbstractMatrix; kwargs...) -> Matrix

Return the zero-based pixel of a world coordinate given in transform order and in the output frame's units, or the one-based pixel with origin=1. Coordinate forms, with_bounding_box, fill_value, and strict act as in pixel_to_world: a world coordinate without a pixel, or whose pixel is outside the bounding box, gives fill_value.

A WCS with an analytical inverse evaluates it. Otherwise a damped Newton solver inverts the forward transform, which needs as many world as pixel axes; with unequal dimensions, world_to_pixel throws an ArgumentError. The solver stops within tolerance pixels or after maxiter iterations, and halves a step at most max_backtracks times. It starts from initial_guess, a pixel that is one-based with origin=1, or from GWCS.jl's own estimate when that is nothing.

A solve that does not converge throws NoConvergence unless quiet=true, which returns the last iterate.

Python equivalent: gwcs.WCS.world_to_pixel_values; Python's world_to_pixel takes astropy coordinate objects instead.

source
GWCS.pixel_to_world_jacobian — Function
pixel_to_world_jacobian(wcs, pixels...; with_bounding_box=true, fill_value=NaN, strict=false, origin=0) -> SMatrix
pixel_to_world_jacobian(wcs, pixels::AbstractMatrix; kwargs...) -> Vector{<:SMatrix}

Return the Jacobian of pixel_to_world at a pixel, the world_n_dim × pixel_n_dim matrix of ∂world_i/∂pixel_j. World coordinates are in transform order and in their frame's units, so celestial axes in degrees give degrees per pixel, with no cos(latitude) factor.

Coordinate forms and keywords act as in pixel_to_world. A pixel without a result, including one whose Jacobian is undefined, gives a matrix of fill_value, or a DomainError with strict=true.

source
GWCS.world_to_pixel_jacobian — Function
world_to_pixel_jacobian(wcs, world...; with_bounding_box=true, fill_value=NaN, strict=false, origin=0, kwargs...) -> SMatrix
world_to_pixel_jacobian(wcs, world::AbstractMatrix; kwargs...) -> Vector{<:SMatrix}

Return the Jacobian of world_to_pixel at a world coordinate, the pixel_n_dim × world_n_dim matrix of ∂pixel_i/∂world_j, with the coordinate forms, keywords, and units of world_to_pixel. With an analytical inverse it is that inverse's Jacobian. Without one it is the inverse of the forward Jacobian at the pixel the numerical inverse finds, which takes world_to_pixel's solver keywords.

An analytical inverse that approximates the forward transform, such as a fitted polynomial, has a Jacobian that differs from the inverse of the forward Jacobian by that approximation. The Jacobian of the exact inverse of the forward transform is inv(pixel_to_world_jacobian(wcs, numerical_inverse(wcs, world))).

GWCS.in_domain — Function
in_domain(wcs, pixels...; origin=0) -> Bool
in_domain(wcs, pixels::AbstractMatrix; origin=0) -> BitVector

Return whether a pixel is finite and inside the WCS bounding box. Without a bounding box, every finite pixel is in the domain. Pixels are zero-based unless origin=1, as in pixel_to_world, and a matrix holds one pixel per column.

GWCS.in_image — Function
in_image(wcs, world...; with_bounding_box=true, origin=0, tolerance=1e-5, maxiter=30, initial_guess=nothing,
         max_backtracks=12) -> Bool
in_image(wcs, world::AbstractMatrix; kwargs...) -> BitVector

Return whether a world coordinate has a finite pixel inside the bounding box. The pixel comes from the analytical inverse or, without one, the numerical inverse that world_to_pixel uses, with its solver keywords; a solve that does not converge gives false. with_bounding_box=false skips the bounding-box test, and origin=1 reads initial_guess as a one-based pixel. A matrix holds one world coordinate per column.

Python equivalent: gwcs.WCS.in_image.

GWCS.pixel_area — Function
pixel_area(wcs, pixels...; with_bounding_box=true, fill_value=NaN, strict=false, origin=0) -> Real
pixel_area(wcs, pixels::AbstractMatrix; kwargs...) -> Vector
pixel_area(wcs, xs::AbstractUnitRange, ys::AbstractUnitRange; kwargs...) -> Matrix

Return the solid angle in steradians that a pixel covers on the sky, evaluated at the pixel center. It is |det J| cos(lat), where J is the Jacobian of the world coordinates in radians per pixel and lat is the latitude. The WCS needs 2 pixel axes and a 2D CelestialFrame output frame in deg or rad. Coordinate forms and keywords act as in pixel_to_world.

Given ranges of integer pixel coordinates, it returns the areas of the pixel grid xs × ys as a matrix indexed like data[x, y], so pixel_area(wcs, axes(data)...; origin=1) covers an image. Each area is the solid angle within the pixel's four corners rather than the value at its center, so it differs slightly from the single-pixel form.

GWCS.get_transform — Function
get_transform(wcs, from_frame, to_frame) -> Union{AbstractTransform,NoInverse}

Return the transform between two frames of wcs, each given by name or as a frame. Toward the output frame it composes the steps between them; back toward the input frame it composes their inverses, and gives NoInverse when a step has none. The same frame twice gives an identity, and a frame not in the pipeline throws an ArgumentError.

Python equivalent: gwcs.WCS.get_transform.

GWCS.transform — Function
GWCS.transform(wcs, from_frame, to_frame, coords...) -> SVector

Evaluate get_transform(wcs, from_frame, to_frame) at a coordinate, given as separate numbers or a static vector. Unlike pixel_to_world, it applies no bounding box and no fill_value. A direction without an inverse throws an ArgumentError.

Python equivalent: gwcs.WCS.transform, which applies the bounding box by default.

GWCS.insert_frame — Function
insert_frame(wcs, input, transform, output; pixel_shape, bounding_box) -> WCS

Return a copy of wcs with a new frame joined to the pipeline by transform. Exactly one of input and output is a frame already in wcs, given by name or as a frame, and the other is the new frame.

When output is new, it is inserted right after input. transform connects them, and the transform that left input now starts at output.

When input is new, it is inserted right before output. transform connects them, and the transform that reached output now ends at input.

Either way the overall mapping changes unless transform is an identity. pixel_shape and bounding_box are accepted only when the new frame becomes the WCS input frame. Then each value wcs has needs a replacement for the new coordinates, or nothing to clear it.

Python equivalent: gwcs.WCS.insert_frame, which changes the WCS in place.

GWCS.fix_inputs — Function
fix_inputs(transform, fixed; atol=nothing, rtol=nothing) -> AbstractTransform
fix_inputs(wcs, fixed; atol=nothing, rtol=nothing) -> WCS

Return transform with some inputs held at constant values, as a transform of the remaining inputs in their original order. fixed is a pair, a collection of pairs, a named tuple, or a dictionary mapping each input to its value. An input is a one-based index or, for a transform with input_names, a name as a string or symbol.

When transform has an inverse, the result has a checked inverse. It verifies the fixed input values and the forward round trip within atol and rtol, and returns NaN for a coordinate outside the fixed-input slice. By default rtol is sqrt(eps) and atol scales with it. With every input fixed, the inverse has no outputs and throws a DomainError instead.

For a WCS, the inputs are pixel axes, named by the input frame's axis_names. The input frame, bounding box, and pixel shape lose the fixed axes.

Python equivalent: astropy.modeling.fix_inputs, and gwcs.WCS.fix_inputs for a WCS.

source
GWCS.numerical_inverse — Function
numerical_inverse(wcs, world...; tolerance=1e-5, maxiter=30, initial_guess=nothing, max_backtracks=12, quiet=false,
                  with_bounding_box=true, fill_value=NaN, strict=false, origin=0) -> SVector

Solve pixel_to_world(wcs, pixel) == world numerically for pixel, to tolerance pixels. The damped Newton solver is the one world_to_pixel uses without an analytical inverse, and it needs equal pixel and world dimensions. With an analytical inverse, which may only approximate the forward transform, the solver starts from that inverse's pixel and refines it against the forward transform. Nonconvergence throws NoConvergence unless quiet=true; the other keywords act as in world_to_pixel.

Python equivalent: gwcs.WCS.numerical_inverse.

Python equivalent: gwcs.wcs.NoConvergence.
